# Workspace UI system

Establish consistent workspace behavior before adding more editing tools. A palette is one reusable shell around its contents, regardless of whether it is docked or floating.

## Palette contract

- A single 23 px header contains the drag handle/name and compact collapse and close controls. Floating hosts must not add a second title bar.
- The header controls are separate hit targets: clicking collapse/close must never begin a move.
- Drag the actual palette, preserving the pointer's grab offset, current width, expanded body height and in-session scroll offset. Dock width takes precedence when docking into a different column.
- The content renderer and vertical scrolling behavior are shared in both hosts. Closing hides a palette; it does not destroy its data. View → Palettes restores visibility.
- Collapse shows only the header and preserves expanded height. Placement, visibility and collapsed state persist; old layouts without collapse state open expanded.
- Show a filled footprint from the same row layout calculation used to render panels. Left/right target quarters insert within a row; the upper/lower center inserts a separate row. Release commits placement; Escape or focus loss restores the pre-drag placement and order.
- Use the same bottom grip for resizing. In a floating host it adjusts both width and body height; docks share column width. Keep the floating header reachable inside the application bounds.

`workspace.rs` owns placement, drag state, shared header and body shell. `panels.rs` and `brushes.rs` supply contents, not separate floating-window chrome. The in-app floating host is an egui Area. The separate-window host uses immediate egui viewports with the same shell and no extra native title bar. Header context menus open independent windows or return them to a side dock/in-app host. OS close hides only that palette; native geometry persists separately. Tab hides in-app panels without closing independent windows. Scroll offset is session-local; document and brush settings do not belong to the host.

## Settings dialogs

Settings dialogs have a single title and visible dismissal actions outside scrolling content. Cancel, title close and Escape discard a draft; Apply commits it. Main window controls remain available while editor controls behind the dialog are disabled. Use the pressure calibration dialog as the current implementation.

## Next UI work

Prioritize consistent keyboard focus, docking-tab groups, arbitrary nested split layouts, accessible names for all header controls, touch target adaptation and cross-window drag docking before expanding the tool catalog. These remain planned. Current docks support rows of equal-width cells, not arbitrary nested split trees. Independent windows use menu commands to dock back; dragging across OS window boundaries is not implemented. Multi-monitor/DPI and macOS/Linux behavior still need native validation. Keep regression checks for drag continuity, docking order, cancellation, resizing, collapse/hide, reopening and preference compatibility.

## Canvas rulers

Rulers use document pixels with major marks at multiples of 100, intermediate marks at 50 and minor marks at 10. Visible document-grid values are mapped to screen positions rather than sampling values at fixed screen intervals. At zero rotation, the origin and every mark translate with the canvas pan; panning never changes the subdivision or label interval. Zoom may omit dense marks/labels using 1/2/5 decimal multiples, but labels remain multiples of 100 pixels. Ruler rendering allocates no mark list and is bounded to 4096 visible marks per axis. Panning does not recompose or upload document pixels.

Each ruler has its own clip rectangle, a separate px corner, and the vertical labels rotate to fit the strip. Rotation retains screen-axis projections of document x/y coordinates; near a 90-degree projection singularity that axis has no marks. This is not an editable guide or a snapping ruler.

## Shared response-curve editor

`apps/parfait/src/curve_editor.rs` is the single UI module for response graphs. It provides a square gray plot, quarter-step grid, input/output labels, percent endpoints, a thin white response line and small violet square control points. It handles point hit testing, selection, dragging, optional insertion/deletion, focused Delete/Backspace and an optional live input marker. Each instance has its own stable UI ID and caller-owned selection.

Callers provide normalized points and constraints: fixed x coordinates versus editable points, fixed endpoints, nondecreasing output versus unrestricted output, maximum point count, labels and plot size. This permits decreasing responses for future tilt/speed settings without weakening pressure constraints. Invalid input is reported without editing it. The widget never owns persistence, device input or brush behavior.

Calibration stays monotonic with fixed endpoints. Brush curves have 2–16 anchors with arbitrary ordered input positions and rising or falling output. Pointer-down on empty plot space inserts and selects an anchor; dragging edits both axes, including a newly added anchor. Input endpoints stay at 0 and 1 but output can change. Releasing an interior anchor more than 12 logical pixels outside the brush plot deletes it; red selection and a release hint indicate pending deletion. Moving back inside cancels that gesture. Delete/Backspace and a button also delete interior anchors. Pointer ownership and grab offset persist through release. Coordinate fields stay present but disabled without selection; numeric editing commits when finished. Arrow keys nudge coordinates by 1%, or 10% with Shift. A faint identity reference, hover guide and live marker distinguish states. Automatic curves use shape-preserving cubic Hermite interpolation without overshooting segment endpoints; manual curves use the handles described below. Version 1 sample arrays migrate to coordinates; version 2 coordinate-only JSON remains readable by version 3. Tilt/speed input dynamics remain future work.

Standard buttons, combo boxes and numeric controls use visible one-pixel outlines, lighter neutral fills and distinct hover/pressed states. Custom icon buttons use the same interaction visuals, including their border.

Brush responses additionally show thin tangent lines and hollow circular handles for the selected square anchor. The first anchor starts selected. Handles take hit-test priority and own their drag through release, including batched press/move/release events. Moving them changes only curvature, not anchor coordinates/count; out-of-bounds handle drags clamp instead of deleting anchors. Left/right handles are independently editable, not automatically paired. Handle X/Y fields and focused arrow keys target the active handle; Delete cannot remove its anchor until the anchor is selected. Auto curvature restores automatic interpolation without moving anchors. Merely selecting a handle preserves an automatic curve.

Manual curves use explicit cubic Bezier segments for both display and brush evaluation. Control input coordinates stay ordered inside each segment and output remains in 0–1; unlike automatic Hermite interpolation, manual handles may produce extrema between anchors. Moving anchors translates adjacent handles, and topology changes preserve unaffected segments while initializing new segments automatically. Version 3 introduced manual handles; current version 4 adds Gap/spray settings and reads versions 1–3 without changing older curve shapes. Device calibration is unchanged and never exposes manual handles.

## Brush properties and details

`brush_stroke.rs` renders the Gap selector as four independently drawn, right-aligned 24-point dot buttons with accessible labels/tooltips and a document-pixel interval summary in the tooltip. Fixed spacing stays editable over 1–1000%; other modes disable but retain that custom value. The selector is shared by Details → Stroke and a pinned Spacing property. Continuous spraying and its enabled-only Rate row remain in Stroke, separate from movement smoothing and per-dab Flow. The controls use the existing thin-bar/number/chevron widget; unsupported ribbon, repeat and input-dynamics settings are explained without fake switches. The static engine preview intentionally does not simulate stationary holds. Footer actions stay outside the scrolling settings.

`brush_details.rs` owns compact property rows, detailed eye/label/numeric/slider rows, a bounded cached preview, and a six-category detail window. Brush size, Ink, Brush tip, Stroke, Correction and Pressure separate tip deposition, pointer filtering and pressure response. The default 410-point-wide window uses a 100-point preview with an overlaid preset name, compact title padding, left-aligned categories and a minimum 240-point settings column. A fixed-width vertical category list stays outside the controls' scroll area. Category guidance appears above the controls; contextual help below follows hovered parameters and describes actual semantics and preview limits. Window chrome uses neutral gray and rectangular outlines; selection alone uses the accent. Unsupported engine features are not presented as working controls. Preview textures regenerate only when brush values change and drawing is idle; visibility changes do not rerender the preview.

Canvas zoom accepts Ctrl/Cmd + plus, equals and minus without changing UI scale. Keyboard zoom keeps the canvas viewport center fixed; wheel, Ctrl/Cmd-wheel and pinch use the pointer anchor. Canvas navigation is suppressed while a brush/calibration dialog or an active drawing stroke owns input.

Modifier routing is per registered combination: unused Ctrl/Cmd combinations fall through to normal tool-key actions (for example Ctrl+B selects the brush and Ctrl+E selects the eraser). Registered shortcuts such as Ctrl+Shift+E retain precedence. Middle-button dragging always pans; Ctrl+Space with primary-button dragging remains the explicit zoom gesture.

## Tool and sub-tool hierarchy

The rail selects implemented drawing families: Ink (P), Sketch (K), Paint (B), Airbrush (A), Eraser (E), plus Hand (H) and Eyedropper (I). The library groups tips by their actual engine behavior, with a separate Materials filter for imported image tips. Filters browse without changing the active brush. Rail actions select a family, clear search/favorite filters and restore that family's session-local draft. Color remains global. Explicit row selection loads saved settings and the preset's erase mode, avoiding accidental erasing after selecting a paint brush.

The library separates browse controls from the Manage menu. Search, family and favorites filters combine. Row stars persist in preferences; missing favorite fields in old preferences/preset files default to false. Family/favorite filters persist, while search and per-family drafts are session-local. Missing built-in family brushes are added on first use when space permits; the 64-entry bound remains enforced.

The tool rail uses 30-point flat icon targets with a one-point vertical gap. Inactive icons have no button frame; selection, hover and keyboard focus remain explicit. Other command and numeric buttons retain their existing outlined style. Icons reuse the bundled Font Awesome Free font without an extra dependency or runtime download.

Sub tools starts with one non-wrapping family dropdown and compact Search, Favorites and Manage actions instead of a second title and wrapping family chips. The dropdown only filters; it does not change the active brush. Search opens an explicitly focused input row; closing it clears the query. A nonempty query always exposes the input. Forty-point list rows use a transparent light-ink sample, a family icon, a clipped/truncated lower-right name and an independent favorite target inside the full-width selection background. Tooltips and accessibility retain full names. Property/detail previews keep their neutral background and dark ink.

Rows show neutral-ink samples generated through the same core brush engine as the property preview. The list owns at most one 240 × 56 cached texture per preset and regenerates at most one visible sample per frame while drawing is idle. Tip size is capped at 38 px; erasing, smoothing, device calibration and artwork colors are not simulated. These are shape/deposition previews, not full-size output promises.

Tool property shows the active preset, modified marker, Save/Restore and selected parameters. `brush_widgets.rs` supplies 42-point palette rows and 28-point detail rows with smaller label/number text: label above a thin outlined fill bar, unframed editable number, stacked chevrons and divider. Size uses a logarithmic bar; numeric editing stays in pixels and other units appear in tooltips. Bar focus supports arrows/Home/End. Size and opacity buttons open target-specific dynamics windows with a shared variable-point response. Unsupported dynamics are explained rather than presented as working switches. Canvas, tool shortcuts and background controls are blocked while brush dialogs own input; Escape dismisses a child before Details. Each numeric parameter has an independently clickable eye in Details. Hiding it never changes its value. `PropertyLayout` is stored with presets, preferences and family drafts. Missing fields use the original four rows. Save/export include visibility; Restore retains drawing color. Hand and Eyedropper show gesture instructions.

New workspaces give the library more height and start with size presets collapsed; existing layouts are preserved until View → Reset palette layout. Color-wheel and navigator previews adapt to their palette body heights to leave room for controls. Very small custom sizes or layouts exposing many properties can require scrolling. Dock tabs and nested layouts remain follow-up work.
