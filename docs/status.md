# 구현 현황

2026년 10월 20일 정리

현재는 기본 그림 작업이 되는 초기 데스크톱 앱이다.
아래 체크는 적힌 범위가 작동한다는 뜻이다. 해당 분야 전체가 끝났다는 뜻은 아니다.
다음 순서는 [개발 로드맵](roadmap.md)에서 본다.
현재는 [레이어 메뉴 완성](layers.md)에 집중한다. 대상 52개 중 11개를 반영했다.
기본 설정 모음 창과 레이어 종류별 상세 편집을 구분해 집계를 바로잡았다.
폴더는 생성 메뉴와 접기, 하위 트리 드래그와 복제, 삭제까지 연결했다.
폴더 통과 합성과 마스크를 반영했고 클리핑 중에는 효과가 멈추는 이유를 안내한다.
접힘 상태 저장과 계층 레이어 합치기는 아직 지원하지 않는다.
레이어 선택 범위의 메뉴와 경계선 표시, 그리기 제한과 선택 마스크를 연결했다.
다음은 새 레이어 종류와 종류별 상세 설정이다. 마스크 연결은 이동과 변형을 함께 만들어야 한다.
채우기와 용지의 색 자료와 합성, 저장 기반을 준비했다. 생성 메뉴와 색 편집 창은 아직 연결하지 않아 완료 수에는 넣지 않는다.

## 그리기

- [x] 펜과 지우개로 픽셀 그리기
- [x] 기본 혼색, 국소 흐리기, 번지기
- [x] 크기, 불투명도, 밀도 조절
- [x] 필압 곡선의 점과 핸들 편집
- [x] 필압에 따른 간격과 한 선의 색 누적 조절
- [x] 붓 모양 가져오기와 프리셋 저장
- [x] 브러시 검색, 즐겨찾기, 이름 변경

크기와 불투명도는 아직 같은 필압 곡선을 쓴다.
혼색은 기존 색을 섞거나 옮기는 방식이다. 새 물감을 더하는 혼색은 아니다.
질감과 산포, 기울기와 속도 입력, 선 시작과 끝의 효과는 남아 있다.
브러시 소재를 읽는 기능은 일반 이미지를 레이어로 여는 기능과 다르다.

## 레이어와 마스크

- [x] 레이어 추가, 복제, 삭제
- [x] 드래그로 순서 변경과 여러 레이어 선택
- [x] 눈 버튼, 잠금, 이름 편집
- [x] 알파 잠금과 14개 합성 모드와 클리핑
- [x] 지원 범위 안에서 레이어 전사와 결합
- [x] 마스크 생성, 그리기, 지우기
- [x] 마스크 켜기와 끄기, 적용과 삭제, 범위 표시
- [x] 원본과 마스크를 골라 비우기
- [x] 활성 원본 전체의 색 변경과 휘도 투명화
- [x] 참조와 밑그림 표시, 기본 설정의 확정과 취소

그림 자료는 픽셀 레이어와 픽셀을 따로 갖지 않는 폴더로 나눈다. 용지는 잠긴 흰 레이어다.
일부 결합은 평면 문서의 연속된 표준 합성 레이어만 지원한다.
폴더 마스크를 그릴 수 있지만 폴더에 적용해 픽셀로 굳히는 기능은 아직 없다.
선택 범위로 만든 마스크와 마스크 연결 이동도 없다.
색 변경과 휘도 투명화도 아직 선택 범위로 제한할 수 없다.
참조 대상 표시는 저장되지만 참조 채우기와 경계 넘침 방지는 아직 없다.

## 작업 화면과 입력

- [x] 팔레트 이동과 도킹과 크기 조절
- [x] 팔레트 숨김과 배치 저장
- [x] 화면 이동, 확대, 회전, 반전
- [x] 문서 좌표를 따르는 눈금자와 픽셀 격자
- [x] 색 선택과 합성된 그림의 한 점 색 읽기
- [x] 단축키 검색, 변경, 충돌 확인
- [x] 이름 있는 작업 기록과 실행 취소와 다시 실행

앱 기본 글꼴은 Pretendard를 우선 쓴다. 대체 글꼴과 운영체제 창은 별도다.
독립 창 사이의 드래그 도킹과 통합 환경설정은 없다.
화면 회전은 그림 픽셀의 회전이 아니다.
메뉴 이름과 화면 문구의 한글화도 더 필요하다.
macOS에서 자모로 나뉜 한글 파일 이름은 글자가 네모로 보일 수 있어 표시 처리를 보강해야 한다.

## 다중 문서: 4단계 기본 경로까지

- [x] 1A·1B: 문서 소유권·편집 상태 ID·내용 digest
- [x] 2A·2B·2C: 탭·비동기 열기·입력 격리·메모리 예산
- [x] 3A·3B·3C: 문서별 복구·세션 목록·재시작·구형 복구 이전
- [x] 4A: 원본 검증·ID 저장 기준·비동기 저장·외부 변경 확인
- [x] 4B: 미저장 닫기 차단·최종 복구와 정상 종료·닫힌 문서 정리
- [x] 파일 메뉴의 `닫기`·`Parfait 종료`를 공통 문서 닫기·복구 종료 경로에 연결
- [x] 원본 저장 진행 표시를 실제 작업·덮어쓰기 확인 상태에서 계산해 취소 후 잔류 방지

일반 실행에 연결했으며 개발용 활성화 옵션은 없다. 원본 저장 중에도 다른 편집과 탭 전환이 가능하다.
정상 종료한 미저장 탭도 복구본으로 복원하고, 원본 연결은 검증한 경우에만 되살린다.
원본 커밋, checkpoint 경고와 복구 실패는 별도로 취급한다. 닫힌 문서는 자동으로 되살리지 않는다.
탭 닫기는 저장하고 닫기/저장 안 함/취소를 제공한다. 앱 종료는 최종 복구와 세션 목록을 기록하며, 미저장 문서는 재시작 때 복원한다.
구현 완료와 OS/실제 펜/성능 검증 완료는 다르다. 실제 검증 범위는 [검증 기록](testing.md)을 따른다.
macOS 실제 앱에서 편집·파일 대화상자·저장 중 입력·정상/강제 종료·원본 오류 복원을 확인했다. 당시 미완료 항목과 기존 NFD 한글 표시 문제 때문에 사용자 경로 전체 완료로 판정하지 않았다. 2026-10-22에는 파일 메뉴 종료와 PNG/JPEG 가져오기·실행 취소·작업 파일 저장을 macOS 실제 앱에서 추가 확인했다. 덮어쓰기 취소와 종료 중 충돌은 자동 회귀 검사로 확인했다. 후속 검증은 [파일 흐름 기록](validation/file-workflow-2026-10-22.md)에 정리했다. [computer use 결과](validation/multi-document-native-2026-10-20.md)에 재현과 증거를 기록했다.

## 파일과 복구

- [x] Parfait 작업 파일 저장과 다시 열기
- [x] PNG 그림 내보내기
- [x] PNG/JPEG를 새 그림 또는 래스터 레이어로 가져오기
- [x] 백그라운드 복구 저장과 정상 종료 시 저장 마무리
- [x] 손상된 최근 기록 대신 이전 기록으로 복구
- [x] 지원하지 않는 설정 파일의 덮어쓰기 방지
- [x] 파일 저장과 복구 저장을 따로 표시
- [x] 저장하지 않은 변경을 제목의 별표로 표시

밑그림 레이어는 작업 파일과 복구 기록에 남고 기본 PNG 출력에서는 빠진다.
밑그림을 포함해 출력하는 선택 창은 아직 없다.

새 그림은 아직 고정 크기이며 크기 선택 창은 없다.
파일 → 가져오기에서 PNG/JPEG를 새 그림이나 레이어로 가져올 수 있다.
새 그림은 이미지 픽셀 크기와 투명도를 유지하며 원본 이미지와 작업 파일 연결을 분리한다.
레이어 가져오기는 원래 크기로 캔버스 중앙에 배치하고 캔버스보다 큰 이미지는 잘라내지 않고 거절한다.
가져오기는 파일당 32 MiB, 각 변 4096 픽셀까지이며 디코더 작업은 한 번에 하나만 실행한다.
JPEG 방향 메타데이터를 적용하고 PNG는 8비트 RGBA로 변환한다. 색 프로파일 변환과 애니메이션 가져오기는 지원하지 않는다.
취소·실패 시 기존 그림과 원본 파일은 유지되며 레이어 삽입은 한 번의 실행 취소로 되돌릴 수 있다.
복구가 끝나도 파일의 미저장 표시는 남는다. 저장한 상태로 실행 취소하면 별표가 사라진다.
복구 뒤 원본 연결은 검증에 성공한 경우만 복원한다. 원본이 없거나 읽을 수 없으면 복구 그림을 남기고 새 파일 저장이 필요하다고 표시한다.
작업 파일 저장은 비동기 작업이며 저장 중에도 추가 편집과 탭 전환이 가능하다. PNG 내보내기는 아직 화면을 잠시 멈출 수 있는 동기 작업이다.
잘못된 설정을 고치는 복구 화면도 아직 없다.

## 검증한 범위

최근 파일 작업은 비동기 원본 저장·문서별 복구 경로의 마무리와 로컬 이미지 가져오기다.
최근 파일 흐름 변경의 자동 검사 결과와 기존 전체 검사 실패는 [2026-10-22 검증 기록](validation/file-workflow-2026-10-22.md)에 구분한다.
코드 형식 검사와 경고를 오류로 다루는 정적 검사도 통과했다.

실제 창의 일부 조작과 저장 후 재실행은 macOS에서 확인했다.
모든 기능과 운영체제, 실제 태블릿과 다중 모니터를 검증한 것은 아니다.
검사 세부 내용은 [검증 기록](testing.md)과 [플랫폼 현황](platforms.md)에 있다.

## 가벼움과 안정성의 남은 조건

바뀐 영역만 다시 그리는 경로와 저장 대기량 제한은 있다.
하지만 레이어 전체 복사와 전체 그림 합성도 남아 있다.
저장 크기 제한과 작업 기록 예산은 앱 전체 메모리의 상한이 아니다.
일부 전체 화면 계산은 목표 시간보다 오래 걸린다.

따라서 가벼움과 입력 지연이 충분히 검증됐다고 말하지 않는다.
실제 메모리와 대기 중 CPU, 펜 입력부터 화면 표시까지의 시간을 더 재야 한다.
현재 측정 결과와 한계는 [성능 기록](performance.md)에 적는다.
