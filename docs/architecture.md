# Architecture

`layers.rs` keeps multiselection, drag preview, solo restoration and inline-name ownership in bounded session state, outside the serialized document. Layer IDs remap these targets after reordering; the index remains the active position cache. Collection actions move shared buffers and reset selection safely on history/document replacement. `layer_ops.rs` owns guarded UI-independent raster transfer, merging, visible copying, flattening and clearing. It reuses masked region composition, not another blend algorithm; only explicit combine commands allocate a full output. Adjacency/visibility/Normal-mode and complete-clipping-chain restrictions protect subset merges from backdrop-dependent changes. Artwork version 4 adds clipping after version 3's stable IDs and alpha lock; preferences v19 protects the 81-command catalog from older readers.

`layer_organize.rs` connects active-only ordering, cyclic layer navigation and a standalone rename dialog through the shared dispatcher. Active ordering preserves other checked layers by ID; selected-set palette moves remain separate commands. Navigation resets additional selection and reuses the existing revision-tag synchronization to avoid compositing/uploading unchanged pixels. Rename owns at most 128 Unicode characters plus one shared pixel-buffer reference, a stable target ID and the opening revision; stale targets cancel rather than edit a replacement document. Only a changed valid confirmation enters History. Dialog state is session-only; artwork and portable brush formats are unchanged.

The application owns UI state. The core owns image state. Storage receives immutable document snapshots and never reaches into the GUI.

## Document Session and State Identity (1A–4B)

`Parfait` owns a `DocumentManager` with one optional `active_session` slot and an ID-indexed map of parked sessions (`parked`), plus a separate `tab_order`. `active_id()` is derived from the slot rather than mirrored. Every session has exactly one owner; a vacant slot has no placeholder document. The small `ActiveSession` dereference adapter is only for guarded active-document code, not an app-wide state copy. The session owns document, History, view, project path/shared saved baseline, recovery counters, stroke/layer transactions, mask targets and layer-list/dialog state. Brushes, color, calibration, keymap, workspace and display settings remain application-wide. There is no mirrored document payload or app-wide Deref compatibility layer.

`SessionKey` combines an OS-random 128-bit `DocumentId` with an independent ephemeral `SessionEpoch`, used by commands, input/dialog owners and egui scopes. Normal single-document New/Open constructs a candidate before replacing the complete session; experimental New/Open inserts a new session instead; Save As retains its key. Restart reuses the persisted document ID and validated edit-state ID but creates a fresh memory epoch. Application session/history initialization and transaction start return entropy failures before mutation, without a fixed-ID fallback. The legacy infallible History wrappers remain for existing core callers; production app edits use the fallible APIs.

`EditStateId` belongs to History: transaction start reserves a random ID, changed commit publishes it and stores the previous ID, Undo/Redo restore IDs, and no-op/cancel preserve state and redo. Collisions against retained history/current/pending IDs are retried. `Document.name` is filename-management metadata, excluded from artwork equality and preserved across History restore/cancel; layer names remain artwork. Original-save status uses the saved EditStateId plus pending-edit detection. A shared snapshot remains available for compatibility, without per-frame digest scans.

`ArtDigestV1` streams validated artwork into SHA-256 using explicit domain/version, little-endian fields, length/presence markers, stable kind/blend tags, normalized float zero and logical mask/selection coverage. Dense and Uniform coverage hash identically; absent selection differs from explicit zero coverage. It includes hidden/locked/draft data, layer IDs/names/order/parents and solid-layer colors, but excludes document name, revision, active index and the next-layer allocator. It is not the SQLite payload checksum. The background source reader computes it, but no app pointer/status path invokes it, and no full canonical image is allocated. Artwork v10 and preferences serialization are unchanged.

`WindowRenderCache` owns the sole canvas texture, active layer/mask thumbnails, selection boundary cache and render tags. Every document entry checks both identity and epoch; a changed key drops the old cache, even at identical revision/LayerId. Widgets and commands are session-scoped and stale keys are rejected. Normal launch now always uses multiple tabs and document-specific recovery. There is no activation flag. The single-document constructor is retained only as an explicit historical test harness. Save/discard/cancel close-choice UI remains deferred; external-source overwrite confirmation is implemented separately.

`document_tabs.rs` finalizes the outgoing stroke/opacity transaction, cancels drag/navigation previews and blocks switching during inline/modal name editing or a details dialog. A fresh pointer-down/touch-start is required after switching. Closing an inactive tab leaves the active cache intact; closing the last permitted tab leaves a genuinely empty workspace. Unsaved non-pristine tabs cannot close until manually saved; application exit commits final recovery and retains them as open tabs for restart.

`project_loader.rs` owns one worker, bounded request/result channels and at most one dispatched load. The UI keeps at most eight path-only requests; decoding/digest runs off-thread. Request ordinals determine insertion position, not completion order. A user-focus generation and latest-request policy prevent delayed focus theft. Cancellation keeps the running reservation until its result is consumed, then discards it without creating a session. Worker errors/panics/disconnection do not replace existing drawings. `project_paths.rs` canonicalizes existing paths or the real parent of a new target, rejects application files/SQLite sidecars/recovery directories and reserves pending open targets. Unix device/inode checks additionally recognize hard links; Windows currently uses canonical paths only. This is in-process conflict prevention, not protection against external replacement races.

`BufferCensus` counts unique Arc allocations by identity and Vec capacity across raster, dense mask/selection, History (including pending before), saved baselines and pinned manual-save snapshots. Uniform coverage allocates no pixel buffer. Experimental admission limits are eight tabs and 512 MiB logical pixels; retained pixels have a separate 1 GiB cap. Stroke starts reserve one target COW channel; other edits reserve conservative document/growth headroom before mutation. History eviction is planned without mutation, oldest inactive entries before active ones, and publishes only if the whole reservation fits. Current state, redo, one undo predecessor, pending before, saved baselines and save pins remain protected. A reader reserves 512 MiB of decoded pixel headroom until consumption; source-save preflight also reserves room to validate an older source snapshot. History navigation checks aggregate logical admission before publishing a restored state.

Storage has one process-local encode/decode work-buffer gate, separate from the pixel census. The 1152 MiB work limit reserves raw size plus a conservative zlib bound before encoding; preallocated capped writers refuse growth beyond that reservation. Read-only `Store::open_read_only` performs no schema migration or creating open. Reads cap checksum/payload sizes before fetching and bound decompressed Vec capacity. Current and legacy raster/mask/selection byte-sequence fields use deserialize-only visitors with exact capacity, so a 512 MiB candidate pixel reservation cannot silently become geometric Vec spare capacity; serialization is unchanged. SQLite internals, GPU resources, strokes' scratch, allocator overhead and total process RSS are not this pixel/work accounting. Artwork serialization, checksum and transaction durability remain v10-compatible.

## Durable Session and Original Storage (3A–4B)

`SessionStore` is an independent, versioned SQLite registry with an 8 MiB logical record cap and lossless OS-native paths capped at 32 KiB. It records open/closed documents, order, active ID, recovery hints, run/clean markers and prepared/committed legacy migration. Future/corrupt registries are not rewritten. The directory lock remains held through shutdown; the startup error path offers a different recovery folder rather than modifying unreadable data.

`Store::load` returns the selected physical `SnapshotHead` independently of a repaired memory revision. Optional metadata binds generation, payload checksum, version and logical artwork digest; invalid metadata drops the binding, not valid artwork. Artwork, metadata and three-generation pruning share one transaction. Ordinary saves invalidate stale optional metadata. The v10 artwork schema/encoding and exact legacy readers remain unchanged.

`StorageCoordinator` owns one worker, at most one coalesced recovery request per live document and a bounded original-save queue. Originals have priority for at most two selections before waiting round-robin recovery. JobKey scopes identity, epoch and request; original jobs additionally capture binding epoch, source head, destination and immutable snapshot. Digest caching retains one value per owner/state, not full images. Pending/running/completed original snapshots and recovery snapshots participate in the pixel census; original inspection has a conservative decoded-pixel reservation. Worker failure releases barriers and reports routed failures; recovery can restart an unavailable worker.

Original save rechecks the approved source head inside an immediate write transaction, commits artwork before reporting success and reports checkpoint/clean warnings separately. The UI applies only matching responses, updates filename/path/baseline after commit and leaves edits made during saving intact. An external change produces an overwrite/Save As/cancel prompt; approval is rechecked on retry. Reservations protect pending opens/saves and other tabs' bindings.

Restoration validates independent original contents without replacing unsaved/crash-recovered artwork. A normally closed saved document can reopen the validated original, including a later valid external change. Missing, corrupt, future or duplicate bindings remain unbound recovery documents. Unreadable/over-limit recovery items remain discoverable and retryable rather than silently discarded. Only order and active tab are persisted UI state; History and view/folding/checks restart fresh.

Closing an eligible tab flushes its final recovery, waits for storage ownership, commits closed, then removes it and its derived files. Cleanup failures retain closed tombstones and block further closes at 32 pending directories. Shutdown settles edits, drains original saves, commits final recovery and atomically records open layout/clean. Untouched empty tabs are not registered. Legacy migration never writes/deletes the old recovery database and resumes the same prepared target after interruption.

## Folder Engine Foundation

Layers can now represent raster content or a pixel-free folder. The bottom-to-top list is a postorder tree: a child's stable parent ID refers to a later folder, and every subtree is a contiguous interval. A bounded 64-node layout pass rejects missing/non-folder parents, cycles and interleaving subtrees. Folder creation, sibling grouping and ungrouping retain child IDs and shared pixel/mask buffers. Names and tree fields participate in edit-state History. New raster content selected on a folder is inserted as its top child; locked ancestors protect insertion and pixel writers.

Flat documents retain their existing compositor. Hierarchical documents build isolated folder results bottom-up using one reusable RGBA row per folder, then apply each folder's mask, opacity and blend in its parent. Sibling clipping does not escape a folder. The no-clipping path shares the existing flat-row routine. Folder picking considers ancestors and their clipping bases but returns raster content, not empty folder pixels.

Artwork v8 appends a folder-only Through blend mode without adding fields. The v7 reader retains its original mode range and tree layout; the exact v6 reader retains roles and masks, while v1–v5 readers produce root raster nodes. Snapshot accounting includes the kind/tag and optional parent ID, while folders own no RGBA array. The 512 MiB limits and conservative raster-dimension preflight remain unchanged. Invalid tree heads recover through the existing previous-generation path.

Documents containing unclipped Through folders use a backdrop-aware row traversal. Children blend directly over their parent's current row, then folder opacity and mask interpolate the before/after result once in premultiplied space. Nested isolated folders keep their own scope. Scratch rows are reused, with at most 1 MiB of row pixels at the 64-node, 4096-pixel-width limits; traversal depth is bounded by the validated tree. No folder-sized image is cached. Clipping a Through folder retains its mode but suppresses pass-through behavior and renders it as an isolated Normal folder. A Through folder cannot serve as another sibling's clipping base. Existing orphan clipping can still be removed. Flat and isolated-only documents retain their preceding paths.

Three typed commands now create, group and ungroup folders. Session-local collapsed IDs are bounded by the 64-node tree. Visible rows keep eye/check columns fixed while indenting content; navigation and edit-history restoration reveal the active node's ancestors. A folder center is an inside-drop target, while row edges are sibling boundaries. Movement normalizes selected roots, keeps each subtree contiguous, rejects cycles and locked parents, and commits only on release. Duplication remaps internal parent IDs while sharing pixel/mask buffers; deletion includes descendants and preserves at least one node. Sibling order commands move complete branches. Snapshot growth preflight includes optional-parent byte changes and mask payloads, never an empty folder canvas. Folder masks use the existing scalar paint path, but applying a folder mask to raster pixels remains disabled. Pixel-only combine commands still refuse hierarchical documents. Preferences v20 preserves older keys and adds no default shortcut or dependency. Folding is not yet persisted across restarts.

## Pixel Selection Foundation

The document owns an optional scalar selection, separate from checked layer rows. None leaves painting unrestricted; an explicit Uniform-0 selection blocks writes. Uniform coverage costs no canvas buffer, and Dense coverage shares one byte per pixel through Arc. Selection edits participate in History and saved-state identity without copying layer pixels. Explicit replacement compares coverage to preserve the original shared buffer and redo on no-ops. Logical memory accounting reserves a full scalar channel for an active selection, including Uniform coverage.

The core derives coverage from selected raster drawing alpha and enabled masks, without display opacity or blend modes. Selected parent folders normalize away duplicate descendants. Folder geometry unions visible children's drawing coverage and applies folder masks, using reusable scalar rows rather than RGBA folder images. Display opacity, blend and clipping are not applied to this geometry operation. Add uses source-over coverage; Subtract removes source coverage multiplicatively, and Intersect multiplies the two coverages. These rules preserve soft edges rather than thresholding to a binary bitmap.

Painting, erasing, blend, blur, smudge and mask painting limit writes by selection coverage. Sample neighborhoods remain unchanged. Capped strokes scale the accumulation limit once, so repeated dabs cannot exceed a fractional selection. Dab retains its preceding layout; writers borrow the independent selection field without cloning its Arc on each dab. Selection-free blend/blur dispatch outside their hot loops to compile-time-specialized writers. Clear, mask restore and pixel conversion also respect coverage; explicit layer combination and export still use complete artwork. Unchanged writes retain pixel/mask identity and revision.

Artwork v9 appends the selection field. Exact v7/v8 tree readers and v1–v6 migration readers create no selection; all preceding masks, roles, IDs and Through behavior remain. Serialized accounting includes the option and coverage payload, and malformed selection lengths use the existing previous-generation recovery path.

Nine shared commands connect layer selection, selection masks and Select All/Deselect/Invert to menus and key assignment. Derived all-zero coverage clears selection and reports an empty result; explicit Uniform-0 engine data remains distinct. Without selection, both selection-mask commands create a fully revealing mask. Source geometry reads hidden or locked selected roots without changing their content. Mask creation requires a single unlocked target, including unlocked ancestors. Gesture/modal ownership blocks mutation. Snapshot preflight reserves worst-case Dense selection or mask payload growth before editing, in addition to the existing logical budget. Preferences v21 retains saved keys; only fresh keymaps gain primary+A, primary+D and primary+Shift+I.

`pixel_selection/boundary.rs` caches two vector dash phases by coverage identity and view geometry, not document revision. It traces visible document-grid edges at the 128 threshold, including holes. Power-of-two display-only LOD bounds traversal and mesh size; an on-canvas label identifies simplified boundaries. Panning transforms document-anchored geometry rather than reanchoring its grid. Phase animation reuses meshes and performs no coverage scan or texture upload. The overlay never enters saved/exported artwork. Free selection tools, reselect, launchers and mask-linked movement remain unimplemented.

## Dependency direction

The next layer-type foundation adds `Fill([u8; 3])` and `Paper([u8; 3])` after Raster and Folder. These retain editable color parameters and empty pixel arrays, not materialized canvas-sized color buffers. Documents containing non-raster content use the existing tree compositor with one reusable RGBA row per non-raster node, at most 1 MiB total. Solid rows are initialized once per composition; raster-only documents retain their preceding flat path. Source sampling, picking, scalar selection and palette previews read the same procedural colors. Fill masks can share active selection coverage. Rasterization explicitly materializes pixels while retaining masks and metadata.

Paper is a unique root at index zero with Normal mode, full opacity and no mask, clipping, alpha lock or drawing roles. It can be hidden, locked, recolored, deleted or rasterized through guarded core APIs; it cannot be duplicated, grouped or moved. Sibling ordering keeps other content above it. The opt-in `new_with_paper` constructor avoids allocating a white raster background. Existing files and the current New Drawing UI retain their original backgrounds until the new type-creation UI is connected. Merely naming a raster layer Paper never converts it.

Artwork v10 stores three extra color bytes for either solid kind. Exact v7/v8/v9 layer layouts freeze their original two kind variants and reject mislabeled newer kinds. V9 retains its selection field; earlier readers retain their established defaults. Snapshot accounting includes the longer v10 header, kind payload, parents and actual mask representation. Creation/rasterization preflight checks both snapshot and logical budgets. The layer-palette creation menu now connects fill/paper creation with the current drawing color. Color-draft preview/editing and the rasterization command remain unconnected; those roadmap items are not marked complete.

`layer_details.rs` owns one session-only active-layer draft, guarded by stable ID, opening revision and pixel identity. Confirm changes only validated metadata as one History transaction; name bytes are bounded by the remaining snapshot budget. Cancel, stale targets and IME confirmation ownership preserve the live document and redo. Reference/draft commands share selected-set flag dispatch and never alter stored RGBA or masks. PNG's `composite_for_export` hides drafts in a shallow metadata copy rather than deleting clipping bases; normal canvas composition remains unchanged. Explicit merges bake the visible result and clear roles on the merged result; ordinary duplication retains them.

```text
parfait (eframe UI)
  ├── parfait-core
  └── parfait-storage ── parfait-core
```

`parfait-core` has no GPU, filesystem, OS or UI dependency. Pixels are straight-alpha RGBA8, layers run bottom-to-top, and a document has one active layer. Every persisted state change advances a monotonic revision, including undo/redo and layer selection. Validation bounds dimensions, layer count, opacity and buffer lengths.

Layer pixel buffers use `Arc<Vec<u8>>`. History and autosave snapshots share unchanged buffers; edits use copy-on-write. History owns a single named timeline and cursor, retaining up to 30 edits plus the earliest retained state. A conservative 128 MiB logical budget divides by current layer bytes to reduce edit capacity, with a minimum of one edit. Future states count against the same capacity. This is not a total process-memory bound or a tiled image engine. The future tile store can replace the pixel representation behind core commands without coupling storage to egui.

History transactions begin lazily, then commit only actual edit-state changes or cancel back to the shared before-state. Commit compares layer metadata and pixel-buffer identity, not a full pixel scan; active selection and revision are excluded. Pixel writers must preserve buffer identity for no-op output. Only a real commit truncates future history. Undo/Redo and direct row restoration share one cursor and always advance the live document revision. Layer opacity/name focus sessions and whole strokes own transactions; choosing another layer finalizes an existing edit without adding a selection row. History rows borrow labels/state flags and do not clone documents during UI rendering. History is session-only.

Brush strokes freeze their brush settings at pointer-down. Samples are interpolated to spaced dabs; a dab applies coverage, opacity and optional pressure scaling. Erasing modifies alpha. PNG tips are masks; the brush color supplies their ink. Raster operations are independent of the view rotation and zoom.

## Raster conversions

`raster_conversion.rs` owns two explicit whole-content commands. DrawingColor changes RGB only where stored alpha is nonzero. BrightnessToOpacity sets those pixels to black with `L = (299R + 587G + 114B + 500) / 1000` and `A' = (A(255-L) + 127) / 255`. These are integer operations on stored sRGB bytes, not a color-managed transform. Originally transparent RGB, masks, metadata and other layers are preserved. Recoloring permits alpha lock; brightness conversion refuses it. Full lock blocks both.

The core validates before writing, compares each result before the first writable access, then uses a single mutable suffix pass. Unchanged output preserves Arc identity, revision and redo. Changed shared buffers still require existing whole-layer COW; no extra canvas scratch/cache or dependency is introduced. The app rejects mask-target/owned-gesture execution, reuses named History and autosave, and leaves selection-limited/non-raster conversion unimplemented.

## Incremental canvas rendering

The application keeps a single session-local overlay target ID, separate from the document and saved preferences. `mask_area.rs` tints the existing checkerboard-composited RGBA output in place according to inverse active-mask coverage; it adds no canvas-sized cache or GPU texture. Its integer RGB mix uses tint `[112, 96, 255]` with maximum alpha 128. Core composition, export and eyedropper reads remain untouched. The navigator shares the display texture. Disabled/hidden masks remain inspectable. New/Open, mask removal/application and restart clear the overlay target.

The renderer compares the post-input active overlay ID with the displayed ID. Overlay transitions force one complete refresh, including layer picks within the same input batch; ordinary drawing tints only existing damage rectangles. Avoiding an extra base-image cache means a toggle also recomputes the full composition once. Pan/zoom/rotation still reuse uploaded pixels. This explicit display cost is distinct from editing document pixels or adding History.

`Document::clear_layer_mask` replaces changed coverage with Uniform 255, retaining enabled state and all original RGBA. Full lock refuses it; content alpha lock does not. Uniform/Dense all-white masks are no-ops, preserving shared buffers/revision/redo. Dense all-white detection runs only on the explicit command, not while rendering menus. Edit's Clear editing target dispatches to this active-only mask action or the existing selected-content clear; the separately named content command never silently changes targets.

Each stroke accumulates clipped, half-open `PixelRect` dab bounds. The UI drains these after each input event and unions them for the frame. `Document::composite_region` returns tightly packed RGBA for that region; the UI applies checkerboard coordinates in document space and sends `TextureHandle::set_partial`. A revision mismatch before processing canvas input forces a full refresh for external edits such as undo, layer changes or project replacement. The navigator reuses the same texture. Damage is transient and never changes the serialized document format.

## Storage protocol

Format v6 is SQLite (`user_version=6`) with `snapshots` and `session` tables. A snapshot stores the complete document using fixed-integer bincode 1 encoding, zlib compression and SHA-256 of the uncompressed bytes. Deserialization is size-limited and followed by document validation. The limit is 512 MiB uncompressed per snapshot. V6 uncompressed bytes begin with `PARFAIT\0SNAP6\0`. Exact separate layouts read prefixed v5 (masks), v4 (clipping), v3 (IDs and alpha lock), v2 (blend modes) and unprefixed v1 (default Normal). V1/v2 layers receive bottom-to-top IDs 1..n, next ID n+1 and alpha lock off. V3 retains its IDs, high-water counter and alpha lock. V1–3 default clipping off; v1–4 default masks absent; v1–5 default reference/draft roles off. Mixed v1–v6 recovery generations remain readable. Saving atomically sets `user_version=6` with the snapshot transaction; older builds reject newly saved files instead of misreading them. Unknown versions, malformed masks and invalid IDs fall back only to validated earlier generations.

Storage `budget.rs` computes valid v6 snapshot bytes in O(layer count), before encoding: 14-byte header + 48 fixed document bytes + UTF-8 document-name bytes + each layer's 39 fixed bytes, UTF-8 name and width × height × 4 pixels. Optional mask payloads add 6 bytes for Uniform, or 13 bytes plus the one-channel dense buffer. Serialization-parity tests cover Unicode names, every blend mode and mask representation. Layer growth/duplication checks the projected snapshot, 512 MiB logical pixel budget, 64-layer limit and ID exhaustion before allocation. Mask creation preflight reserves room for later dense storage. Uniform masks conservatively reserve one canvas-sized channel in logical/History budgets even though they allocate none. Save preflight rejects oversized documents without encoding or replacing any generation. This does not increase the format limit or change SQLite durability.

`layer_mask.rs` provides optional Uniform/Dense mask coverage and independent create/remove/enable/apply core operations. Effective alpha is rounded once as `(raw_alpha * coverage + 127) / 255`, before existing opacity/blending. Disabled/absent masks bypass coverage. Apply writes only alpha and removes the mask, preserving RGB and pixel-buffer identity when no bytes change; full/alpha locks refuse destructive application. Both clipping bases and clipped sources use their own mask alpha. Merges bake masks into results without applying them twice; raw-content Clear retains masks. Transfer down conservatively refuses affected masks. History compares enabled state, Uniform values or Dense Arc identity without a full scan. The application exposes active-only reveal-all/hide-all creation, delete/apply/enable and adjacent content/mask target thumbnails. Mask drawing shares Stroke interpolation/spraying and Dab coverage, writing one-channel coverage without changing raw RGBA. Paint restores and Erase hides, independent of drawing color; disabled masks and blending operations refuse input. Full lock blocks editing; alpha lock does not block mask painting. Selection-shaped creation and linked transforms remain unimplemented; mask-area display and target-aware clearing are described below. Flat and clipped chains without effective masks have separate fast paths; clipped scratch remains one RGBA row.

Every layer has a unique nonzero `LayerId(u64)` below the document's persisted next-ID counter. New/duplicate/composite-result layers get new IDs; reorder and ordinary edits retain them. Undo, redo and cancellation keep the highest issued counter, so discarded branch IDs are not reused. The counter alone is not an edit. History compares layer IDs as well as metadata and pixel identity, making a swap of otherwise identical layers a real edit.

Alpha lock changes RGB only on existing nontransparent pixels, preserving every alpha byte and all channels of fully transparent pixels. Paint interpolates stored RGB; Erase interpolates toward white instead of removing coverage. Capped strokes retain their contribution limit. Blend/Blur/Smudge use unpremultiplied sampled color weighted by sample alpha. Lazy destination writes avoid COW, damage and revision changes for identical output. Strokes freeze the target ID and alpha-lock flag. Full layer lock still blocks painting; Clear/Transfer conservatively refuse alpha-locked affected layers. Configurable content eraser policy is not implemented. Mask editing operates on separate coverage and intentionally ignores content alpha lock, except for destructive mask application.

Clipping is composition-only metadata: continuous clipped layers share the nearest structural unclipped base. A hidden/zero-opacity/zero-alpha or missing base suppresses its chain without changing any pixels. At each pixel the base's blend mode first supplies its color against the accumulated backdrop; clipped source colors then blend within full coverage using their own modes and alpha/opacity. The final color is composited once with the base's original alpha and opacity. Thus clips never inflate base coverage or inherit a base blend mode a second time. This is an independently defined stored-sRGB, rounded RGBA8 algorithm, not a color-managed or grouped-layer engine. Eligibility is filtered once per base into at most 64 borrowed references; structural chain boundaries remain independent of visibility and selection masks. Groups without eligible clips take a separate flat path. Clipped groups read each source sequentially across a reusable row of RGBA scratch, at most 16 KiB at 4096 pixels wide, allocated only when needed. The row's alpha marks actual clipping contribution, preserving the original path and rounding at pixels without contributions. A coverage-255 RGB helper is tested byte-for-byte against general blending; general source-over and brush math remain unchanged. There is no added full-canvas clip buffer, persistent cache or background work. Region/full paths share this implementation. Metadata changes invalidate the view; pixel damage updates use the same complete structural chain. Hit testing checks the base as well as the candidate layer. Raw painting is unrestricted by clipping. New blank layers inserted inside a chain inherit clipping; reorder/delete may leave an invisible orphan flag, which can be disabled. Partial merges/transfers require chain closure, while visible/full operations bake the display.

SQLite uses WAL and `synchronous=FULL`. In one transaction, insert the new revision and prune to three newest generations. Readers examine generations newest-first and verify decompression, hash, decoding, and dimensions. Fallback advances beyond the broken generation so the next save becomes the head. A corrupt SQLite container itself may prevent fallback; the original file is preserved.

An OS file lock protects the recovery directory. `session.clean` becomes false on startup and true only after the normal final save succeeds. Worker acknowledgments contain revisions; UI saved state is compared to the current revision. The pending snapshot slot replaces older pending work, but never cancels a transaction already in progress. Failed saves retain the in-memory document and retry after a delay.

Normal app exit joins the worker after submitting the final snapshot. Manual Save writes an independent SQLite project and checkpoints its WAL. New/Open first write a rotating backup of the existing document. External database writing is unsupported.

`project_state.rs` keeps one session-local successfully saved/opened `Document` baseline, sharing its pixel/mask buffers. Dirty checks compare edit metadata and buffer identity, not revisions or pixel bytes. Recovery acknowledgments never advance this baseline. Undo to the original shared buffers clears the marker; separately recreating identical bytes may conservatively remain dirty. Selection, view and tool changes are not edits. Recovery restart has no trusted project-path association and starts without a baseline.

Save prepares a named candidate and commits live name/path/baseline only after snapshot save, clean marking and checkpoint succeed. A late disk error may leave committed disk data even though the live association stays unchanged. Open validates and backs up before replacing the live document; successful New clears the association. Known recovery, backup, preferences and lock paths and their SQLite sidecars are refused as explicit project targets, including existing symbolic aliases; broken symlinks are refused. This is not a hardlink or concurrent external path-change security boundary. Manual project writes, backup and PNG export remain synchronous. No format, worker or dependency is added.

## Module responsibilities

- `app.rs`: document lifecycle, save/load/export, background save status.
- `canvas.rs`: screen/document transforms, pointer dispatch, texture upload and view drawing.
- `rulers.rs`: bounded, document-anchored coordinate ruler layout and clipped painting, with no document or storage mutation.
- `panels.rs`: tools, navigator, layer controls and status.
- `menus.rs` and `menus/catalog.rs`: bounded static menu hierarchy, shared command/toggle dispatch and nonexecuting planned entries, without adding placeholder commands or serialized state.
- `editing.rs`: stroke/layer transaction boundaries, cancellation, layer selection and preflighted layer creation.
- `layer_commands.rs`: shared layer command guards, collection/flag edits and palette controls.
- `history_palette.rs`: named session rows and shared Undo/Redo command controls.
- `shortcuts.rs` and `shortcuts/`: event routing, typed command dispatch, bounded keymap/hint cache and draft editor with durable Apply.
- `theme.rs`: visual style, embedded Pretendard text families and the separate icon family; no synchronous system-font discovery.
- `display.rs`: validated display preferences, view commands and the live display-settings window. These never mutate document pixels or history.
- `widgets.rs`: palette controls, color wheel and accessible icon buttons using the bundled Font Awesome Free font.
- `document.rs`: layer data, validation, compositing.
- `brush.rs`: sample interpolation, shared tip coverage and operation dispatch.
- `raster_brush.rs`: local color-reservoir blending and premultiplied separable blur, with per-stroke bounded scratch.
- `smudge.rs`: spatial per-stroke pixel pickup/carry, premultiplied bilinear resampling and masked deposition.
- `wash.rs`: optional per-stroke Paint/Erase contribution limits, sparse bounded tiles and baseline recomposition.
- `history.rs`: bounded named snapshot timeline, transactions and one restoration cursor.
- Storage `lib.rs`: on-disk format, validation, atomic saves and session locks.
- Storage `worker.rs`: queue ownership, asynchronous writes and acknowledgments.

Keep editor commands typed, introduce a tile representation before promising large canvases, and define schema migrations before changing persisted fields.

The desktop workspace uses a compact menu/command bar, a narrow tool rail, scrollable brush/color palettes and a navigator/layer palette. Standard action icons come from the pinned Font Awesome Free asset, with tooltips and accessibility labels; see its bundled attribution. Layer thumbnails are refreshed from document pixels when the revision changes, deferred until pen-up during strokes. Rulers show screen-axis projections of document coordinates when the view is rotated.

`workspace.rs` owns typed palette placement, ordered side docks, drag/drop targets and floating in-app Areas. Docked and floating palettes share one header/body/grip renderer; drag keeps live geometry, collapse/visibility persist, and scroll offset is carried between hosts within the session. `preferences.rs` validates and persists versioned layout and brush state to a separate SQLite file using atomic row replacement; workspace preferences do not change the artwork format. Invalid or newer preferences are reported and preserved. `brushes.rs` owns the library, bounded image-tip ingestion and versioned JSON `.pbrush` interchange. `chrome.rs` owns the frameless title bar and native viewport window commands. Closing still passes through the save acknowledgment path.

Brush dynamics belong to `parfait-core`: `ResponseCurve` holds 2–16 normalized input/output points with input endpoints at 0 and 1 and strictly ordered interior inputs. Outputs may rise or fall. The core evaluates these exact coordinates before size/opacity modulation without per-sample allocation or resampling. Spacing, flow, roundness, angle and simple low-pass smoothing are independent settings. Brush settings are frozen at pointer-down. Smoothing can trail the cursor; this is not predictive or velocity-aware stabilization. The canvas keeps navigation and painting mutually exclusive for a held pointer gesture. Native pressure samples use the existing windowing backend; no native driver API is embedded in the core.

## Cross-platform boundaries

`ResponseCurve.controls` optionally stores two normalized Bezier control coordinates per anchor interval. Absence retains the automatic Hermite evaluator. Conversion initializes mathematically equivalent Bezier controls; pressure evaluation solves monotonic Bezier x using 24 bounded bisections and evaluates y with no allocation. Input loops, non-finite/out-of-range handles and count mismatches are rejected. Display uses the same evaluator. Preferences and `.pbrush` version 3 introduced explicit controls; version 4 added gap/spray settings; version 5 adds raster operations and reads versions 1–4. Neither artwork snapshots nor device calibration change.

Windows, macOS and Linux are equal desktop targets, with mobile apps planned later. Keep document state, brush algorithms, editor commands and project-format migrations independent of platform APIs. Desktop and mobile should share the Rust core and exchange the same versioned project files.

OS integration belongs behind application-level interfaces for file access, data directories, input, lifecycle and rendering capabilities. The current desktop implementation uses eframe, native file dialogs and filesystem paths directly; those integrations still need separation before a mobile frontend is added. Do not assume the current UI framework or OpenGL backend is the final mobile solution.

Mobile suspension may skip normal exit callbacks. Recovery must rely on incremental committed saves, with lifecycle notifications used to request an additional save when possible. Touch and stylus input need normalized samples and gesture routing rather than simulated desktop shortcuts. See [platforms](platforms.md) for planned work and validation gates.

`pressure.rs` provides monotonic device calibration independent of brush presets. `calibration.rs` owns a draft editor and bounded test-pad data (4096 marks/samples). Only Apply updates the global curve and persists preferences. A missing calibration field in older JSON defaults to identity. Device calibration precedes the brush response. Test-pad strokes are separate from artwork and undo history. Preferences use version 18 (reading versions 1–17); `.pbrush` exports use version 8 (reading versions 1–7). Preferences v10 adds the seventh, initially hidden History placement to six-palette records without changing their geometry or keys. Explicit opacity accumulation, shortcuts and pressure spacing are retained. The curve deserializer converts five-output arrays to their exact original input coordinates and retains automatic evaluation for coordinate-only records. New curves store points and optional manual controls. Invalid curves are rejected. `Document` does not contain `Brush`, so brush-setting migrations do not change artwork layout. The separate artwork changes introduced stable IDs/alpha lock in v3, clipping in v4 and mask data in v5.

`GapMode` resolves Fixed/Wide/Normal/Narrow into a document-space interval from maximum diameter, independent of UI scale. Fixed optionally multiplies by `minimum_spacing + (1 - minimum_spacing) * spacing_curve.sample(pressure)`, retaining the 0.5 px floor. This independent curve does not change diameter/opacity responses. Each dab sets the next interval from its interpolated pressure; residual distance crosses event boundaries. Disabled dynamics and automatic Gap modes retain legacy pixels. `Stroke` freezes settings at pointer-down. `Stroke::spray` accepts elapsed seconds and calibrated pressure, accumulating time independently of frame count. Each call consumes at most 100 ms and stamps at most 12 additional dabs; it shares damage tracking and has no OS timer or persistence access. `canvas.rs` requests repaint only during an active timed stroke and ends it on release, pointer/focus loss, modal interruption or navigation. `brush_stroke.rs` owns the reusable mode selector and detail-only spraying controls, not persistence.

Dock rows group palettes horizontally and retain vertical row order. `dock_layout` is shared by rendering and drop preview; simulation occurs on a cloned workspace before committing. Header context menus switch a palette into an immediate native viewport or back to an in-app host. Native close requests hide the palette, and an optional native rectangle stores screen position and expanded size independently from its in-app rectangle. Older preference records default to separate rows and no native rectangle.

`curve_editor.rs` owns shared response graph rendering and interaction. Callers choose constraints and keep ownership of values/persistence; calibration and brush pressure use the same widget with different point policies. See the [UI system](ui-system.md) before adding another graph implementation.

## Layer blending

`parfait-core/src/blend.rs` defines 14 separable RGB blend modes and alpha-aware source-over composition. Blend functions operate on stored sRGB values. Transparent backdrop areas retain source color; source alpha is multiplied by layer opacity. Normal keeps the existing fast path. Full and damaged-region rendering share this implementation, also used by PNG export. `Layer::blend_mode` is included in snapshots, duplication and history; changing it increments the document revision for full texture invalidation.

`response_curve.rs` evaluates shape-preserving cubic Hermite responses without heap allocation. It is shared by device calibration, brush pressure and graph rendering/markers so the displayed curve matches drawing behavior. Saved node coordinates remain compatible; non-linear responses now interpolate smoothly rather than linearly.

`brush_details.rs` owns the compact brush-property palette and categorized live editor. Its preview renders a small temporary document through the core brush engine, caches one texture, and never edits artwork. `brushes.rs` retains import/export/library operations and shared preset saving. The detail editor blocks canvas gestures and global shortcuts while open; title-bar close, Close and Escape retain live edits.

`PropertyLayout` retains the original nine-boolean array plus a defaulted two-boolean blend/blur extension, independent of core brush physics and artwork serialization. Active preferences, preset records and per-family session drafts carry it. Missing layout fields default to the original four property rows, preserving older JSON preferences and `.pbrush` files. The detail eye column and palette use one property definition for labels, ranges, enablement and semantics. Spacing and pointer smoothing are exposed in separate Stroke and Correction categories. Contextual help and visibility changes have no document/history side effects.

## Raster brush operations

`BrushOperation` separates Paint/Erase/Blend/Blur/Smudge from tip shape. The legacy `erase` flag remains a compatibility alias taking precedence over the new field. Missing operation defaults to Paint. This is an operation layer, not a complete independent tool-family metadata model: paint family filters still derive from tip type. Version 5 introduced blending; version 6 gates spatial Smudge so older applications reject rather than reinterpret new operations as painting.

Blend samples a coverage-weighted premultiplied RGBA mean on the first dab without editing pixels. Later dabs combine the local mean with the carried sample according to Color stretch, then interpolate destination pixels by shared tip/opacity/flow/pressure coverage. It adds no drawing color and does not transport texture. Blur snapshots only the dab plus a clipped halo, computes separable sliding box averages in premultiplied RGBA and applies the same coverage. Automatic radius is ceil(pressure-adjusted radius × 0.1), clamped to 1–32 document pixels; manual radius is rounded and bounded to the same range. Transparent RGB cannot leak into visible color. Both operations read/write only the active visible unlocked layer and report output damage only when bytes change.

Blur allocates bounded source/horizontal scratch once per stroke and reuses it; default per-dab Paint/Erase and Blend have no additional scratch allocation. Maximum validated 512 px / 32 px-radius blur capacity is 3,739,840 bytes, excluding existing whole-layer copy-on-write/history costs. Blank/uniform blur avoids copy-on-write. The tagged Scratch owns None, Blur buffers, Smudge patches or capped Paint/Erase contributions, never all buffers at once. The engine preview seeds two-tone pixels for blend/blur and striped pixels for Smudge, uses the actual operation and retains the existing 38 px cap. Pigment-adding wet mixing, clone stamping and reference layers are not implemented.

`OpacityMode::PerDab` is the default and preserves legacy pixels. `PerStroke` affects only Paint/Erase. Wash retains the starting layer's shared RGBA buffer and lazy 64²-cell `f32` contribution tiles. For each pixel, `next = old + max(target - old, 0) * coverage * flow`, bounded by the greater of target/old. Target is opacity times optional mapped pressure. Paint source-overs the fixed stroke color onto the baseline using next; Erase scales baseline alpha by `1 - next`, preserving RGB. Lower subsequent pressure cannot undo stronger contributions. A new stroke starts from the current pixels. Transparent erase and identical opaque ink avoid tile allocation, pixel copy and damage. Other writes acquire unique destination pixels only after an actual byte change. A fully covered maximum 4096² document needs at most 64 MiB payload plus 32 KiB tile indexing on a 64-bit target, excluding allocator overhead and existing whole-layer COW/history. This is transient scratch, not another RGBA image or a document-format change. Width/height/active-index guards reject incompatible writes; callers must not replace/reorder a layer during an active stroke. Blending operations retain their existing scratch and ignore the saved accumulation mode.

Smudge picks up a spatial patch on its first dab without changing artwork. Later movement dabs combine each previous patch sample with the current layer sample according to Color stretch, finish the entire next patch before writing, then deposit through shared coverage/opacity/flow/pressure. Two reused `u16 × 4` premultiplied buffers reserve at most 516² cells each (4,260,096 bytes total). Out-of-document samples are transparent. Fractional coordinates use bilinear sampling; unchanged radius copies previous cells directly, while changed pressure radius resamples normalized patch coordinates and may scale texture. Stretch 0, zero effective opacity and stationary input do not edit pixels. Invalid/blocked dabs reset pickup. The active layer can lose alpha when transparency is carried. Only actual byte changes advance revision/damage. Spacing and frozen settings remain shared; Smudge disables stationary spraying and does not request its timer. No filesystem, GUI dependency or additional runtime library is introduced.

Preference maintenance caches the last successfully saved typed `Preferences`, not its JSON payload. Before cloning or encoding, it compares every persisted field; `Workspace::same_preferences` excludes skipped interaction/layout caches. New persistent fields must be added to the comparison and its serialization-parity tests. Loaded image masks are shared between live and cached settings. Failed writes retain the previous snapshot so edits remain retryable; unsupported loaded records are never overwritten. Root maintenance runs once per second while idle and at 100 ms while saving/drawing/closing, without changing input-driven redraws or autosave durability.


Palette label colors use a bounded, identity-sorted document metadata sequence. A drawing with labels writes v12; unlabeled drawings retain the exact v10 raster or v11 native-content encoding. Readers migrate v1–v11 to empty labels, and SQLite's declared version never decreases. The v12 snapshot budget includes the content-vector and label-vector prefixes and each eleven-byte label. Labels have a conditional domain in ArtDigestV1, preserving prior unlabeled digests; they affect edit identity and history but never composited RGBA. Layer removal prunes labels before recording UI history, and subtree/raster duplication preserves them.
