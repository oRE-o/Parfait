## 텍스트·벡터와 저장

레이어 → 새 레이어 → 텍스트 / 벡터에서 만들고, 레이어 → 텍스트 / 벡터 내용 편집에서 수정한다. 텍스트는 내장 Pretendard 또는 선택한 TTF/OTF 파일을 문서에 포함한다. 글자 내용·크기·색·위치와 벡터 경로의 점·두께·색·닫기·채우기를 편집할 수 있다. 기본 한국어 완성형·라틴 문자와 줄바꿈을 지원하며 복잡한 문자 조판, 가변 글꼴 축 편집, 캔버스에서 점을 직접 잡는 벡터 도구는 이 구현의 범위에 포함되지 않는다.

정렬의 기본값은 텍스트의 공백/줄 높이를 포함한 배치 경계와 벡터의 선 두께를 포함한 경계다. 각각의 옵션은 실제 글자 윤곽과 선의 중심 경로 경계로 바꾼다. 이동값은 문서 픽셀 단위로 반올림한다. 정렬 기준과 가이드는 문서별 세션 상태이며 그림 파일에는 저장하지 않는다.

레이어에는 재생성 가능한 픽셀 캐시를 두고 텍스트·벡터 원본은 불변 공유 데이터로 보관한다. 캔버스 기하 변환은 원본 행렬과 캐시를 함께 갱신한다. 픽셀 브러시·색 보정·내용의 부분 변형·마스크 적용·초해상도 전에 레이어 메뉴의 명시적인 래스터화를 요구한다. 래스터화는 보이는 픽셀을 그대로 유지하고 Undo로 원본을 복원한다. 텍스트·벡터가 포함된 그림의 합치기는 먼저 래스터화해야 한다.

기존 래스터·폴더·채우기·용지 그림은 기존 v10 바이트 형식으로 계속 저장한다. 편집 가능한 텍스트·벡터가 있고 레이어 구분 색상이 없는 그림은 v11을 사용한다. 레이어 구분 색상이 있는 그림은 v12를 사용한다. 각 형식을 지원하지 않는 구버전 앱에서는 열 수 없다. v1~v10 읽기, 정상 그림의 동일 v10 쓰기, v11 재열기·손상된 최신 스냅샷 폴백·프로세스 강제 종료 복구를 검사한다. 그림에서 원본 데이터를 없애도 이미 v11로 표기된 데이터베이스의 버전을 낮추지 않는다.

## 사용 범위와 확인할 점

- 자동 채색·음영·확대는 결정적인 로컬 알고리즘이다. CSP의 AI 결과나 기능 동등성을 주장하지 않는다.
- 변형은 캔버스 핸들과 수치 입력을 함께 쓴다. 메인 그림은 확인 전까지 바뀌지 않는다. 핸들 이동은 즉시 표시하고, 픽셀 미리보기는 하나의 작업 스레드에서 최신 설정으로 갱신한다. 메시 접힘은 거부한다. 마스크 썸네일에서 마스크만 변형할 수 있으며, 내용 썸네일에서 선택이 없으면 내용과 마스크를 함께 변형한다. 내용에 선택 범위와 마스크가 동시에 있는 부분 변형은 여전히 거부한다.
- 클립보드 arboard 소유권을 유지한다. egui-winit 0.36.2가 이미지 전용 클립보드의 Ctrl/Cmd+V 이벤트를 넘기지 않는 경우가 있어 신규 키맵의 붙여넣기는 Alt+V다. 메뉴 붙여넣기도 사용 가능하다. 기존 키맵에는 새 값을 주입하지 않는다.
- 이 작업의 실행 환경은 Windows x86_64다. 화면 캡처 OS 권한, 실제 게임패드/Bluetooth/펜 하드웨어와 macOS·Linux 경로는 별도 현장 검증이 필요하다. xcap 0.9.8은 Wayland 캡처를 일부 상황에서 불완전하게 지원한다고 명시한다. 이 앱의 Wayland 캡처 경로는 검증되지 않았다. Linux X11 빌드에는 xcap 시스템 라이브러리와 gilrs의 libudev가 필요하다. [플랫폼 문서](platforms.md) 참고.
- 문서/스냅샷 각각 512 MiB, 캔버스 각 변 4096px, 레이어 64개 한도를 유지한다. 네이티브 콘텐츠는 글꼴 16 MiB, 텍스트 128자, 경로 256개/총 65,536점, 렌더 작업 상한을 검사한다. 소재는 로컬 256묶음, 화면 캡처는 16,777,216물리 픽셀로 제한한다.
- 문서 편집은 세션·리비전과 잠금을 검사하고 한 번의 Undo로 복원한다. 설정/추출색 변경은 그림 내역을 만들지 않는다. 외부 계정·원격 서버·모델 다운로드 없이 동작한다.

## 로컬 변형 조작 보강

- 영역 안 드래그로 이동, 모서리/중간 핸들로 배율 조절, 바깥 회전 핸들, 자유/왜곡/원근 모드의 모서리 조작을 지원한다. 회전 중 Shift는 45도 단위, 배율 조절 중 Shift는 종횡비를 유지한다.
- 메시 격자는 가로/세로 2~16점이며, 격자 수 변경은 점 이동을 초기화한다. Shift+클릭으로 점을 추가 선택하고 함께 드래그한다.
- 퍼펫은 빈 영역 클릭으로 핀을 놓고, 핀 드래그로 이동하며 선택 핀의 원형 핸들로 회전한다. Alt+클릭으로 삭제한다. 원본 위치와 이동 위치를 따로 보관하고, 핀별 강체 변환을 거리 가중으로 혼합한 전방 변형을 Delaunay 삼각 메시로 역매핑한다. 고정 핀은 메시의 정점이므로 위치를 정확히 유지한다. 메시 역전은 거부한다. 다른 제품의 고유 알고리즘과 동등성을 주장하지 않는다.
- 미리보기는 원본 문서의 공유 스냅샷에서 계산한다. 문서 세션/리비전/변형 설정이 일치하는 결과만 표시한다. 취소는 행 단위 계산을 중단시키며, 원본 픽셀과 Undo/Redo를 바꾸지 않는다. 완료된 미리보기의 문서 버퍼는 확인 시 재사용해 픽셀을 다시 계산하지 않는다. 메모리가 부족한 미리보기는 내역을 삭제하지 않고 거부한다. 적용은 하나의 실행 취소 단계다. 저장되는 프로젝트 형식은 이전 구현과 동일하다.


## 색조 보정·이미지 편집 재작업 (2026-10-20)

사용자가 요청한 변경 목록과 실제 적용 내용:

- **레벨 보정:** RGB/Red/Green/Blue별 설정을 함께 유지한다. 원본의 알파×선택×마스크 가중 히스토그램, 검정/감마/흰색 드래그 핸들, 입력 및 출력 범위와 자동 조정을 제공한다. 자동 범위는 양 끝 0.5%를 제외하며 빈 채널·단색은 항등 범위다. RGB 공통 변환 후 개별 채널을 적용한다.
- **톤 커브:** RGB별 2~16점. 그래프 클릭으로 추가, 드래그로 이동, 내부 점을 바깥으로 끌거나 Delete로 삭제한다. 끝점의 입력 위치는 고정하고 출력값은 바꿀 수 있다. 배경에 원본 히스토그램을 표시한다. 기존 독립 구현인 shape-preserving cubic Hermite 보간을 색조 보정에서도 재사용하며 LUT를 한 번 계산한다.
- **컬러 밸런스:** 그림자·중간조·하이라이트 값을 각각 유지하고 동시에 적용한다. 세 계조의 겹치는 선형 가중치로 RGB를 보정한다. 휘도 유지 시 원래 가중 RGB 휘도로 되돌린 후 색역 밖 값을 회색 방향으로 축소한다.
- **그라데이션 맵:** 2~32개 색 노드의 추가·선택·이동·삭제, 위치 수치, 구간별 혼합 중간점, 색 순서 반전, sRGB/선형광 혼색, 자체 작성한 흑백·석양·청록 예제를 제공한다. 노드 불투명도, 사용자 그라데이션 세트 저장, 제품별 지각적 혼색 모드와 동등한 결과는 구현하지 않았다.
- **나머지 보정:** 밝기/대비 자동 조정, HSV 기반 색조/채도/명도, 정수 2~20단계 계조화, 2치화의 투명도 유지 선택, 로컬 참조 이미지 적용도와 밝기 유지. 2치화에서 투명도 유지를 끄면 원래 알파가 0보다 큰 픽셀을 불투명하게 하며 완전 투명한 여백은 새로 칠하지 않는다.
- **공통 조작:** 수치·그래프 변경을 하나의 백그라운드 작업에서 캔버스에 미리 표시한다. 미리보기 on/off, 원본 비교, 초기화, 다시 계산, 확인·취소를 제공한다. 색조 보정은 다중 선택 래스터 레이어에 한 번의 Undo로 적용하며 잠긴 레이어가 포함되면 전체를 거부한다. 마스크는 보정된 원본 색 위에 계속 작동한다. 미리보기 메모리 부족은 Undo/Redo를 지우지 않는다.
- **이미지/캔버스 크기:** 픽셀 크기·배율·종횡비 잠금, 최근접/투명도 고려 쌍선형 보간, 캔버스 9개 기준점·직접 위치 지정·잘림 안내. 선택/마스크는 기존 최근접 재매핑을 보존한다. 크기가 달라지는 편집은 별도 썸네일로 미리 확인한다. DPI/인쇄 단위 메타데이터, 추가 고급 보간법은 아직 없다.
- **자동 음영:** 실루엣의 2회 chamfer 거리장으로 둥근 높이장을 만들고 선형 시간의 가로/세로 박스 평활화를 거친 뒤 법선을 계산한다. 평행/점 광원·각도·높이·표면 반경·농도·부드러운/2~4단계 음영·암부/명부 색을 조절한다. 노란 광원 핸들을 캔버스에서 드래그한다. 선택적으로 참조 표시 래스터 레이어의 어두운 선을 높이장에 반영한다. 밑색 버퍼를 유지하고 별도 클리핑 레이어 두 개를 만든다. 단일 활성 밑색 레이어가 대상이며 이미 클리핑된 밑색은 거부한다. 입체 구조·해부학·가림·투영 그림자를 추론하지 않으며 CSP 자동 음영과 같은 결과라고 주장하지 않는다.

미리보기는 원본 세션·리비전·파라미터를 비교해 낡은 결과를 버린다. 색조/LUT·픽셀·음영 계산은 행 단위로 취소할 수 있다. 기존 캔버스 크기·영역 채색·참조 색 통계 처리는 시작/종료 시 취소를 확인하며 내부 계산 도중에는 완료까지 시간이 걸릴 수 있다. 완성된 미리보기 문서는 확인 시 픽셀 버퍼를 재사용한다. 새 저장 포맷이나 네트워크 의존성은 추가하지 않았다.

참고 자료는 공개된 [색조 보정 효과 사용 설명서](https://help.clip-studio.com/ko-kr/manual_kr/390_filters/색조_보정_효과.htm)와 [자동 음영 사용 설명서](https://help.clip-studio.com/ko-kr/manual_kr/390_filters/자동_음영.htm)의 조작 항목이다. CLIP STUDIO와 PAINT 실행은 확인했지만 Windows 캡처가 `FrameArrived timed out` / `window capture timed out`으로 실패하여 실제 제품 대화상자의 시각 비교·마우스 조작 검증은 완료하지 못했다. 바이너리·모듈·모델·독점 로직을 추출하거나 저장소에 반입하지 않았다. 공개된 조작 개념을 참고해 코드를 독립적으로 작성했다.


## 메인 UI와 문서 탭 후속 수정

문서 탭을 메뉴 위에서 캔버스 열의 맨 위로 이동했다. 탭 클릭 전환·순서 드래그·우클릭 이동/닫기·가운데 클릭 닫기·열린 그림 목록을 제공한다. 파일 → 닫기 및 창 → 캔버스 → 다음/이전도 실제 명령이다. 수정한 그림에는 저장/저장 안 함/취소를 표시하고 저장 성공 후에만 닫는다. 다음/이전은 현재 탭 순서 기준이며, CSP의 편집 이력 순서 전환·OS 창으로 분리·나란히 편집은 아직 없다.

색조/채도/명도의 세 슬라이더를 실제 egui 포인터 이벤트로 조작하여 캔버스 미리보기 픽셀이 달라지고 취소 시 원본과 History가 보존되는지 검사한다. 편집 창 ID를 기능별로 분리해 다른 메뉴의 창 위치를 공유하지 않게 했다. 설정·텍스트/벡터 창도 같은 위치·닫기·Esc 처리 규칙을 사용한다. 위치 기억은 현재 앱 세션 안에서 적용된다.

공식 참조: [캔버스 창 배치 변경](https://help.clip-studio.com/ko-kr/manual_kr/270_canvas/캔버스_창_배치_변경.htm), [색조 보정](https://help.clip-studio.com/ko-kr/manual_kr/390_filters/색조_보정.htm). CSP의 실제 메뉴 클릭 검증은 캡처 오류로 미완료이며, Parfait 입력 검사와 구분한다.


내비게이터도 캔버스와 동일한 미리보기 텍스처를 사용하고 비활성 UI의 회색 틴트를 그림에 적용하지 않는다. 색조·채도 조절은 무채색을 착색하지 않으며, 명도 양 끝은 흰색/검정이 된다. 선택 범위와 원래 투명도는 유지한다. 이는 공개 조작 개념에 맞춰 독립적으로 정한 계산이며 CSP 내부 수식과 동일하다는 주장은 아니다.


### 캔버스 크기·해상도 직접 조절 (2026-10-22)

이미지 해상도 변경과 캔버스 크기·기본 설정은 작업 영역에 실제 그림과 8개 크기 핸들을 표시한다. 캔버스 크기는 가운데 십자 핸들로 범위를 이동할 수 있고, 해상도는 종횡비 고정을 따른다. 숫자·기준점·핸들은 같은 편집 초안을 사용한다. 추가 영역은 용지·채우기색과 투명 체크무늬로, 잘리는 영역은 어둡게 표시한다. 확인 전까지 원본 픽셀과 내역은 유지하며, 취소는 모든 초안을 버린다. 크기 드래그는 기존 텍스처를 표시하고, 용지·네이티브 콘텐츠와 해상도의 정확한 미리보기는 포인터 조작이 끝난 뒤 기존 단일 작업 스레드에서 계산한다.
